## 2. 공통 정보 파이프라인
공식 API·공개 데이터 → 합법 수집 → 정규화/중복 제거 → 발행기관 원문·시각·상태 검증 → 언어별 번역 초안 → 분야별 리뷰 → 게시 → 수정/만료 추적 → 알림 → CRM 기록

정보 레코드 필수 스키마:
- `id`, `site`, `type`, `title`, `country_iso`, `region_code`, `industry`, `language`
- `source_url`, `source_owner`, `source_type`(official/third_party/user_submission), `fetched_at`, `source_updated_at`
- `deadline_at` (원문 시간대 보존), `status` (unknown/potentially_open/confirmed_open/closed/withdrawn)
- `evidence_refs`, `verified_at`, `reviewer_id`, `review_status`, `confidence_label`
- `translation_method`, `translation_reviewed`, `revision`, `license_or_reuse_basis`, `expires_at`

**주의:** 날짜가 미래인 것과 실제 접수 중이라는 것은 다르다. 발주기관 공식 원문 확인 없이는 'confirmed_open' 사용 금지. 실시간 재난 경고는 반드시 원출처·시각·지리적 범위 명시. 종교적 예언은 검증된 공공 재난 예보와 구분한다.

## 3. 공통 고객 여정
익명 방문 → 관심 분야/국가 선택 → 무료 답변/샘플 → 실제 필요 진단 → 정보 근거 표시 → 상담 신청 → 단일 고객·기관 ID로 CRM 생성 → 담당자 배정 → 응답 SLA → 결과/만족도 설문 → 재문의·개선 루프.

자동 의뢰는 명시적 고객 동의, 수집 최소화, 요청 이력과 담당자 확인을 필요로 한다. 가입·발송·구독·결제는 자동 실행하지 않는다. 마케팅 메시지는 별도 동의와 수신 거부 지원 필수.

## 4. 후보 앱과 비용 통제
- GitHub Actions: 코드 검사, 배치 작업, 변경 이력. 기존 연결 활용.
- Supabase/Postgres: 계정/권한/레코드/RLS, 연결 전 권한·유료 한도 검토.
- Huginn 또는 자체 서버리스 스케줄러: 이벤트 점검. 서버 운영비/유지관리 대비.
- Firecrawl: 허용된 사이트의 페이지 추출만; API/호스팅비·이용약관 검토.
- Twenty: CRM 후보, 자체호스팅 핵심 기능과 유료 기능 분리.
- listmonk: 동의 기반 뉴스레터 후보, 실제 SMTP 전송비 별도.
- Chatwoot: 고객상담 후보, 서비스 운영비와 권한 필요.
- Canva/Descript: 승인받은 게시 콘텐츠 제작 보조. 원본 권리·로고 검토.
- ChatGPT × Claude: 초안·번역·검수 보조. 데이터와 고객 식별정보 임의 외부 전송 금지.

**원칙:** 앱을 한꺼번에 설치하지 않는다. 한 서비스에서 수집→검증→이용→상담→피드백 폐회로를 증명한 뒤 확장한다. 자동충전 OFF, 유료 API 호출 상한, 비용 감시, 캐시 및 재시도 상한.

## 6. 서비스 목표(KPI, 달성 주장 아님)
- 고객 만족(CSAT) 95%+ 목표, 설문 응답 수와 편향 함께 보고
- 유효한 핵심 공고의 출처 링크 표시율 100%, 실제 공식성 검증율 별도 집계
- 모든 상담 접수에 추적 ID 발급률 100%
- 업무시간 내 첫 응답 4시간 목표 / 긴급한 재난 정보는 사용자 지역의 공식 기관 경보로 안내
- 홈페이지 가용률 99.9% 목표, 별도 실제 모니터링 필요
- 월간 지출 상한을 소유자가 명시 승인하기 전까지 유료 자동화를 켜지 않음

## 7. 배포 승인 게이트

절대 자동 결제·자동 가입·무단 게시·외부 발송·운영 브랜치 변경을 수행하지 않는다.
