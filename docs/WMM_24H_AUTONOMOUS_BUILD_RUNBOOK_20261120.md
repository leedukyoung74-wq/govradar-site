테스트 통과는 운영 배포와 다르다.

## 즉시 실행할 공통 원칙
1. 기존 원본/운영 브랜치 `main`, `live`는 읽기만 한다. Draft PR에서만 수정, 무단 병합·배포·DNS 변경 금지.
2. 유료 API, 자동충전, 광고, 메일/카카오 메시지 실발송, 결제, 고객정보 수집/이관은 사전 승인 없이는 절대 실행하지 않는다.
3. 한 회차당 하나의 독립적인 작업만 선정하고, 테스트 실행 결과와 커밋 SHA를 기록한다. 실패 시 롤백하고 재시도 횟수를 제한한다.
4. GitHub Actions = 테스트/수집/검사 엔진. GitHub Actions 자체가 AI 코딩을 수행하는 것은 아니다. 코드 생성은 별도 승인된 Claude Code/Codex 실행 환경과 사용량 예산이 필요하다.
5. 시간제 GitHub `schedule`은 워크플로 파일이 **기본 브랜치**에 존재해야 실행된다. Draft PR에 넣는 것만으로 정기 실행되지 않는다.
6. 개인 Windows PC에서 계속 실행하려면 PC/전원/인터넷이 유지되어야 한다. 대안은 승인된 클라우드 runner/Work 환경이며 별도 제한과 비용을 확인해야 한다.

## 실행 반복 루프
입력: 기존 계획+이전 보고서+열린 Draft PR → 이슈 1개 선택 → 소스 분기 작업 → 오프라인 테스트 → Draft PR 커밋/CI → 성공·실패 로그 → 다음 대기열.
- 결과가 모두 동일하면 반복 작업을 멈추고 차단 원인을 기록한다.
- 작업 간 실행 상태를 파일·이슈·PR로 남긴다(대화 메시지 자체를 영속 저장소로 가정하지 않는다).
- 오류 감시가 필요하면 시간별 상태 보고, 실제 코드 생성은 승인된 에이전트의 독립 실행 주기에 따라 처리한다.
