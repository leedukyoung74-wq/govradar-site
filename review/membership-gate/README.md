# GOV RADAR 회원 접근 제어 검토본

WMM 홈페이지의 GOV RADAR 입구에서 회전 영상과 공개 소개로 이동합니다. 로그인 또는 무료 가입을 선택하면 자체 가입 화면이 열립니다. 이메일 인증을 마친 회원은 GOV RADAR를 열람할 수 있습니다. 국별 화면, 레이더 데이터, 피드와 비공개 검토 화면의 직접 요청은 서버에서 회원 여부를 확인합니다. 분석 등급은 기존 `/mkey` 기능이 계속 확인합니다.

## 로컬 검토

현재 폴더에서 `node --test`를 실행합니다. 테스트는 브라우저와 회원 공급자를 대신하는 고정 응답을 사용합니다. API 키, 외부 계정, 네트워크 요청이 필요 없습니다.

완성된 `dist`와 `cf`가 있는 프로젝트를 별도 검토 폴더에 조립합니다.

```powershell
python prepare_review.py --source ../govradar-integrated-preview --output ./stage
```

`stage/functions`는 Cloudflare Pages 프로젝트 기준 함수 폴더이고 `stage/public`은 빌드 출력 폴더입니다. 원래 프로젝트와 `dist`에는 쓰지 않습니다. 공개 빌드에 `private` 원본 파일을 넣지 않습니다. 이 검토본은 새 배포를 실행하지 않습니다.

검토 프로젝트가 있으면 `node --test`는 복사된 실제 소개, 가입, 한국 리포트, 데이터 파일도 읽습니다. 인증 공급자의 응답은 테스트용입니다. 공개 접근 화면은 미들웨어가 정확한 언어 주소에서만 렌더링하고, 두 공개 스크립트는 개별 정적 파일로 읽어 캐시하지 않습니다.

## 운영 반영 전 확인

1. 실제 회원 인증 공급자와 분리된 Cloudflare 검토 환경에서 이메일 가입, 인증 메일, 로그인, 비밀번호 재설정, 로그인 유지, 로그아웃과 Google 로그인 설정을 승인받은 테스트 계정으로 확인합니다. 검토 도메인을 사용하는 경우 Pages 환경에 `GOV_RADAR_CANONICAL_ORIGIN`을 설정하고, 이메일과 OAuth의 반환 주소가 검토 도메인과 일치하는지 확인합니다. 한국어와 영어 가입 화면을 검토하며 나머지 지원 언어의 접근 화면은 영어를 사용합니다.
2. Cloudflare Pages Functions 일일 무료 한도 초과 시 정적 파일이 공개되지 않도록 **Fail closed**를 선택합니다. 사이트와 프로젝트 기본 주소에 적용되는 캐시 규칙도 점검하고 기존 공개 응답을 제거합니다. 보호 자산마다 인증 확인이 한 번 실행되므로 무료 사용량으로 예상 트래픽을 감당할 수 있는지 측정합니다.
3. `wmm-govradar.netlify.app`는 별도 서비스입니다. 이 검토본으로 해당 호스트의 이전 대시보드를 차단할 수 없습니다. Netlify Identity의 기존 회원 계정을 유지하면서 이전 정적 대시보드와 데이터, 활성 배포 별칭을 비활성화하거나 보호합니다. 공개 GitHub 저장소와 기존 배포를 포함한 다른 사본에서 접근 가능한 데이터는 별도로 확인합니다.
4. 운영 전 세 호스트에서 비회원 직접 접근과 응답 본문을 다시 확인합니다. 인증된 무료 회원과 분석 회원으로 권한 차이를 확인한 뒤, 접근 제한을 적용한 상태로 운영 변경을 승인하고 반영합니다.
5. 대시보드의 기존 Netlify 로그인 코드와 계정 기능은 브라우저 저장소에 토큰을 보관합니다. 검토본도 호환을 위해 이 동작을 사용합니다. 공개 가입 화면은 같은 사이트 스크립트만 실행할 수 있으며, 대시보드의 전체 콘텐츠 보안 정책과 브라우저에서 토큰을 제거하는 작업은 별도 검토가 필요합니다.
