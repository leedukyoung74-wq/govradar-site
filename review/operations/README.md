# GOV RADAR 통합 운영

ChatGPT는 요청과 일일 보고를 한 채팅에서 관리합니다. Drive의 기존 `01_지시접수`에는 날짜별 원본 한 건이 남습니다. Windows는 공식 데이터 갱신을 확인하고 사이트 검토 화면을 만듭니다. Claude Code는 같은 작업번호로 시간·상태·건수만 받아 하루 한 번 교차 검수합니다. 기존 GitHub 수집기는 공개 데이터 브랜치를 계속 갱신합니다.

| 범위 | 주기 | 확인 기준 |
| --- | --- | --- |
| 정부사업·입찰·정책·언론·환경·공개 국방기관·보건·경제·환율·제재 | 매일 | 기관·발행일·갱신 시각·독립 출처 확인. 국가 6~10곳과 특별지역 2~4곳 순환 검토 |
| 지진·기상·비상 경보 | 기관 발표 기반 | USGS 5분·미국 NWS 15분 목표. 지연 시 마지막 성공과 담당 기관 원문 표시 |
| 국가·특별지역 출처 보강 | 순환 검토 | 193개 주권국과 23개 지역 구분. 동일 발행주체의 서로 다른 웹페이지는 한 곳으로 집계 |
| 변경 반영 | 검토 완료 뒤 | 단일 작업번호의 검토본 또는 초안 PR, 확인되지 않은 자료는 후보 상태 유지 |

NWS는 미국 범위입니다. CISA KEV는 공개된 취약점 권고 목록입니다. 국방은 공개 정책·기관 행정 정보만 다룹니다.

## 실행

`python run_ops.py --repo <trusted source checkout>`는 운영 사이트가 읽는 공개 자료를 점검하고 `state/latest.json`과 날짜별 검토 화면을 생성합니다. 통합 조사 원문은 `state/inbox/GPT_DAILY_YYYYMMDD.txt` 또는 `--research`로 받습니다. 날짜·형식 검사를 통과한 자료는 로컬 검토 폴더에 저장됩니다. 주장별 사실 확인은 결과의 구조 검사와 별도로 기록합니다.

`--use-included-claude`는 기존 구독 로그인과 추가 사용량 비활성 상태를 확인하고 1일 1회만 시도합니다. 실패 또는 한도 도달은 해당 작업번호에 남습니다. 클라우드 검사에는 Claude·Drive 자격증명이 필요 없습니다.

Windows 결과는 08:20, 11:20, 15:20, 19:20 한국시간에, 채팅 보고는 각 시간의 45분에 예약합니다. `public_notices.py`는 보안 권고를 15분 간격으로 읽고, `prophecy_watch.py`는 한 시간 간격으로 기존 영상 감시를 실행합니다. 최초 등록에는 `Set-LocalReportSchedule.ps1`을 사용합니다. 실행 전 이 환경의 기존 작업과 경로가 맞는지 확인합니다.

GitHub 검토 워크플로는 승인된 데이터 브랜치를 읽고 상태 화면과 사진이 포함된 전략 검토안을 산출물로 남깁니다. 예약 트리거는 기본 브랜치에서 활성화해야 합니다. 지금도 기존 GitHub 데이터 업데이트는 노트북과 독립적으로 실행됩니다. Windows 노트북이 종료·절전이거나 사용자가 로그아웃하면 Windows 예약은 다음 로그인 및 실행 가능한 시점에 따라 지연될 수 있습니다.
